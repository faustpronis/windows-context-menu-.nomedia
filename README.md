# FolderTools

[![release](https://img.shields.io/github/v/release/faustpronis/windows-context-menu-.nomedia?display_name=tag&sort=semver)](https://github.com/faustpronis/windows-context-menu-.nomedia/releases/latest)

Небольшая утилита для Windows, которая добавляет в контекстное меню папки пункт
**FolderTools** с подпунктами:

1. **Создать .nomedia** — создаёт (или дополняет) в текущей папке файл `.nomedia`
   с отметкой времени и путём этой папки.
2. **desktop.ini (DeskEdit)** — открывает текущую папку в редакторе `desktop.ini`
   [Desktop.ini Editor](https://www.sordum.org/10084/desktop-ini-editor-v1-2/) (DeskEdit).
3. **Настройки…** — открывает окно настройки папок для копирования и перемещения.

Пункт появляется при клике правой кнопкой по папке, по пустому месту внутри папки
и по корню диска. Регистрация идёт в `HKEY_CURRENT_USER`, права администратора не нужны.

## Пункт в меню «Создать»

После установки в меню **Создать** (правый клик по пустому месту в папке) появляется
пункт **Файл .nomedia**. Он создаёт `.nomedia` с текущей датой, временем и путём папки —
как команда «Создать .nomedia», но одним движением.

Техническая деталь: `ShellNew` в реестре не умеет задать точное имя файла — оболочка
сама придумывает имя («Новый файл.nomedia») и затем передаёт его команде. Поэтому
пункт зарегистрирован через значение `Command`, а не `NullFile`: утилита получает
этот файл-заглушку, пишет настоящий `.nomedia` в ту же папку и удаляет заглушку.
Значит, пункт работает и тогда, когда `.nomedia` в папке уже есть, — запись просто
дополнится по общим правилам.

Ограничение: меню «Создать» есть только у папок на диске (в проводнике). В диалогах
открытия/сохранения файлов и на рабочем столе пункта не будет.

## Что пишется в .nomedia

Первая строка — время и дата, вторая — путь к папке:

```
18:53:23  18.11.2026 Ср
D:\SHARE\SYNCTHING\
```

Правила:

- Формат даты и дня недели не зависит от региональных настроек Windows:
  дни недели жёстко заданы (`Пн`…`Вс`), формат — `ЧЧ:ММ:СС  ДД.ММ.ГГГГ`.
- Если файла `.nomedia` нет — он создаётся.
- Если файл есть, но записи для этой папки в нём нет — новая запись добавляется
  в конец, отделённая пустой строкой.
- Если запись для этой папки уже есть (путь сравнивается без учёта регистра
  и типа разделителей) — ничего не меняется.
- Кодировка — UTF-8 без BOM, перевод строки — CRLF.

## Установка

1. Распакуйте архив целиком, например в `C:\Tools\FolderTools`. DLL находятся в
   подпапке `FolderTools_dlls`; не отделяйте её от программы. Рядом с `FolderTools.exe`
   должен оставаться `FolderTools.exe.config` — он указывает загрузчику .NET искать
   библиотеки в этой подпапке и содержит необходимые перенаправления сборок.
   Папку установки потом не перемещайте: путь к exe записывается в реестр.
2. Откройте настройки FolderTools и на вкладке **Прочее** нажмите
   **«Установить / обновить»**. Это регистрирует меню и очищает старые отдельные
   пункты копирования/перемещения, а также удаляет устаревшие DLL из корня папки
   программы (текущие зависимости находятся в `FolderTools_dlls`). Альтернативно
   можно запустить `FolderTools.exe -i`.
3. Правый клик по папке (или по пустому месту внутри неё) → **FolderTools**.

После каждого обновления воспользуйтесь **Прочее → Установить / обновить** или
запустите `FolderTools.exe -i`, чтобы обновить пункты контекстного меню и удалить
legacy-регистрации старых версий.

`FolderTools.exe.config` — конфигурация CLR для .NET Framework 4.8. Загрузчик
читает её до запуска приложения, поэтому перенести её в `FolderTools_dlls` нельзя;
обычный .NET Framework также не поддерживает встраивание этого файла в exe.

Если программа не запускается, откройте командную строку в папке установки и
выполните `FolderTools.exe /debug`. Диагностический журнал создаётся в
`%LOCALAPPDATA%\FolderTools\startup.log`; если папка профиля недоступна, используется
временная папка Windows. Ключ `/debug` также фильтруется при обычном запуске, поэтому
он не передаётся командам программы.

Удалить пункты Explorer можно кнопкой **Прочее → Удалить меню**; настройки и пароли
при этом сохраняются. Командная строка остаётся доступна: `FolderTools.exe -r`.

## Копировать в / Переместить в

В контекстном меню файлов и папок остаётся один корневой пункт **FolderTools** с
иконкой приложения. Действия **«Копировать в»** и **«Переместить в»** доступны внутри
него как подменю; там же всегда есть пункт **«Настройки…»**. Список папок назначения
и правила отбора задаются в окне настроек («FolderTools → Настройки…» или
`FolderTools.exe settings`).

Для каждой папки назначения задаётся название, путь и список шаблонов расширений:

| Шаблон | Что означает |
|---|---|
| `*` | любой файл, в том числе без расширения |
| `*.txt` | все файлы `.txt` |
| `*.jp!` | `.jpg`, `.jpeg`, `.jpX` — `!` это ровно один любой символ |
| `фото!.jpg` | `фото1.jpg`, `фотоA.jpg`, но не `фото10.jpg` |
| `txt` | то же, что `*.txt`: точку можно не писать |
| `[папка]` | только папки |

Регистр не важен. Шаблонов у одной папки может быть несколько — они объединяются.

Поведение меню:

- Пункт папки виден только для тех файлов, чьё расширение подходит под её шаблоны.
- Если выделено несколько файлов разных типов, каждый файл уходит в свою папку:
  расширение проверяется отдельно для каждого файла, а не для всего выделения сразу.
- Папки назначаются отдельно (`[папка]`), чтобы файлы и каталоги не смешивались.
- Одинаковые имена не перезаписываются: к имени добавляется ` (2)`, ` (3)` и так далее.
- Целевая папка создаётся, если её ещё нет.

### Удалённые папки SFTP

Откройте вкладку **Remote** в настройках и нажмите **«Добавить SFTP…»**. Для каждого
получателя задаются отдельные параметры подключения и папка назначения. Там же можно
просматривать, изменять и удалять SFTP-получатели. При добавлении укажите название,
сервер, порт, удалённый путь, пользователя и пароль. Кнопка **«Обзор…»** рядом с
удалённым путём подключается к серверу и позволяет выбрать каталог через список
папок (переход внутрь — двойной щелчок, вверх — кнопка «Вверх»). Для уже заданного
получателя выберите его на вкладке **Remote** и нажмите **«Изменить…»**; также можно
использовать кнопку **«Изменить SFTP…»** на вкладке папок назначения.
Кнопка **Test connection** на вкладке **Remote** (или **«Проверить соединение»** в
окне SFTP-настроек) отдельно показывает результат подключения и авторизации, наличие
удалённой папки, возможность чтения и пробную запись временного файла с последующим
удалением. Причина ошибки выводится рядом с этапом, который не прошёл. Если сервер
доступен, но папки нет, программа предложит создать её вместе с отсутствующими
родительскими каталогами. Если пробный файл удалось записать, но не удалить, отчёт
отдельно сообщит, что он остался на сервере. При первом подключении программа покажет
SHA-256 fingerprint SSH-ключа сервера. Сверьте его с администратором сервера до
подтверждения: после этого fingerprint запоминается, и дальнейшие подключения
отклонят другой ключ.

Для SFTP-получателей рядом с **«Копировать в»** и **«Переместить в»** доступно подменю
**«Выбрать папку»**. Оно открывает встроенный файловый менеджер; после выбора каталога
можно разово скопировать или переместить выбранный объект, не меняя постоянный путь
назначения. В менеджере отображаются права текущей (родительской) папки в octal-виде,
а также сообщённые сервером UID/GID. Стартовая папка подключения настраивается отдельно
от обычной папки назначения.

Закладки хранятся в рамках конкретного подключения, поддерживают категории и могут
содержать chmod-пресеты для файлов и каталогов, а также необязательные числовые UID/GID.
Перед каждой SFTP-передачей можно выбрать такой пресет или вручную задать chmod и
владельца/группу. Применение UID/GID зависит от возможностей сервера и прав пользователя;
если сервер отклонит запрос владельца/группы, операция будет отмечена ошибкой, а источник
при перемещении останется на месте. SFTP не предоставляет надёжного универсального списка
аккаунтов, поэтому UID/GID вводятся вручную. Windows SFTP-серверы могут не поддерживать
Unix-права; управление Windows ACL интерфейсом не реализуется.

При конфликтах доступны **«Заменить все»**, **«Пропустить имеющиеся»** и
**«Заменить, сохранив прежнее»**. Последний вариант переименовывает удалённый объект в
`имя-conflict-YYYY-MM-DD_HH-mm-ss.ext`; если такое имя уже занято, добавляется числовой
suffix. Одноимённые каталоги сливаются рекурсивно без удаления серверных объектов,
которых нет локально; конфликты файлов разрешаются выбранной политикой. При Move
локальный источник удаляется только после обработки всех элементов; если вложенный
объект пропущен или метаданные не удалось применить, источник сохраняется.

Передача файлов и менеджер папок в этой версии реализованы только для SFTP. Наличие
вкладки Remote и поддержку rclone/bclone не следует считать поддержкой выбора облачных
каталогов или облачной передачи — эти функции пока не реализованы.

Действие **«Копировать в»** загружает выбранные файлы и папки, включая вложенные
каталоги. **«Переместить в»** удаляет локальный оригинал только после успешной передачи
и применения выбранных метаданных.

Можно задать до семи резервных адресов — по одному на строке в формате `host` или
`host:port`; если порт не указан, используется основной. При отправке адреса
проверяются параллельно, а передача начинается через первый успешно подключившийся
адрес с подтверждённым SSH-ключом и доступом к заданной удалённой папке. Fingerprint
закрепляется отдельно для каждого адреса; неизвестный ключ всегда требует явного
подтверждения. Во время загрузки показываются общий прогресс, текущий файл и скорость;
передачу можно отменить. После неё отображается число успешных объектов, ошибки и
объём отправленных данных. При отмене/ошибке неполный локальный объект не удаляется.

Автоматические Unix-права задаются списком расширений (например, `.sh, .py, .php`)
и восьмеричным режимом `0644`/`0755`. По умолчанию правило выключено (список пустой).
Автоматическое правило chmod по расширению сохраняется. При задании transfer-пресета
права файлов устанавливаются после полной загрузки и проверки размера, до публикации;
права каталогов применяются после обработки содержимого. Если chmod/chown не удался,
исходник при перемещении остаётся на месте.

Пароль SFTP хранится в двух формах. Для переноса между компьютерами он находится
в `FolderTools.settings.json` только в зашифрованном виде; мастер-пароль не попадает
в этот файл. Шифрование использует PBKDF2-HMAC-SHA256 с 600 000 итерациями и AES-256-CBC
с проверкой HMAC-SHA256. Подсказка мастер-пароля — обычный текст и не участвует в
шифровании. Впервые добавляя пароль, задайте мастер-пароль на вкладке **Прочее**.
При смене мастер-пароля существующие доступные записи расшифровываются и заново
шифруются; старый пароль проверяется до любых изменений.

После разблокировки расшифрованные SFTP-пароли и мастер-пароль можно кэшировать в
Windows Credential Manager текущей учётной записи на этом компьютере. Это избавляет
от повторного ввода; **«Забыть на этом компьютере»** удаляет локальный кэш и старое
DPAPI-хранилище, не меняя переносимый зашифрованный конфиг. Старое хранилище
`%LOCALAPPDATA%\FolderTools\sftp-credentials.dat` читается для миграции: вкладка
**Прочее → Задать / изменить пароль и подсказку** переносит доступные старые записи
в новый зашифрованный формат.

Скопируйте `FolderTools.settings.json` через выбранный вами синхронизируемый каталог
или клиент синхронизации. FolderTools не ведёт облачный список устройств и не может
удалённо очистить Credential Manager другого компьютера. Действие **«Забыть»** нужно
выполнить на каждом устройстве отдельно. Смена мастер-пароля не отзывает уже
синхронизированные офлайн-копии конфигурации и ранее расшифрованные локальные кэши;
для очистки кэшей откройте программу на каждом таком устройстве. Программа также не
сливает конфликтующие версии JSON: избегайте одновременного редактирования настроек
на нескольких компьютерах и разрешайте конфликты самим клиентом синхронизации.

Старые пароли DPAPI остаются доступны на прежнем компьютере, пока пользователь явно
не выполнит миграцию или не нажмёт **«Забыть на этом компьютере»**. Если пароль был
задан только в локальном старом хранилище, он не переносится до миграции в настройках.

### Категории

Чтобы меню не разрасталось, папки можно объединить в категории. Категория — это
подменю: например «Фото» → «Снимки», «Скрины». Папки без категории остаются в корне.
Удаление категории не удаляет папки, они возвращаются в корень.

### Иконки пунктов меню

У каждого пункта назначения (локальной или SFTP-папки) можно задать свою иконку:
выберите пункт в списке и нажмите «Обзор…» в строке «Иконка». Принимаются `.ico`
и `.png`; PNG с прозрачностью конвертируется в настоящий многоразмерный ICO.
Файл иконки копируется в подпапку `icons`
рядом с программой (создаётся автоматически), а в настройках сохраняется
относительный путь вида `icons\<id>-<hash>.ico`. При смене изображения имя файла
меняется, чтобы Explorer не показывал закэшированную старую иконку. Поэтому папку с
программой можно целиком перенести или заархивировать, не теряя иконки. Если файл иконки удалить,
пункт вернётся к иконке программы.

### Где хранятся настройки

Всё лежит рядом с программой, в одной папке:

- `FolderTools.settings.json` — папки назначения, шаблоны расширений, категории,
  зашифрованные пароли SFTP и подсказка мастер-пароля, иконки, путь к DeskEdit,
  уведомления и выбранный remote-движок;
- `icons\` — копии выбранных иконок.
- `remote-tools\` — скачанные исполняемые файлы rclone и/или bclone;
- `remote-config\` — отдельные конфиги `rclone.conf` и `bclone.conf`.

Вкладка **Remote** позволяет выбрать rclone или bclone, установить/обновить выбранный
движок, увидеть его версию, получить список backend-ов непосредственно из этого
бинарника и проверить настроенные remote-подключения. Проверка выполняет листинг
корневого каталога remote; это не проверка записи. У каждого движка свой конфиг.
bclone — неофициальный форк; он может содержать backend-ы, которых нет в rclone
(например, Terabox и другие дополнительные службы). Переключение на rclone не удаляет
bclone или его конфиг, но уникальный backend не станет доступен в rclone.

Это первый этап интеграции: мастер GUI создания remote-подключений и передача файлов
через облачные backend-ы из FolderTools пока не реализованы. До их появления remote-ы
настраиваются средствами самого rclone/bclone. Учитывайте, что конфиг rclone по
умолчанию не обязательно зашифрован целиком; «obscure» отдельных паролей не заменяет
шифрование файла. Задайте пароль конфигурации средствами rclone, если файл содержит
секреты, и храните его отдельно от синхронизируемого конфига.

Пути внутри папки программы записываются относительными, поэтому перенос папки
ничего не ломает. В списке получателей дважды щёлкните SFTP-папку или нажмите
«Изменить SFTP…», чтобы изменить её параметры. Окно настроек открывается только
в одном экземпляре: повторный вызов активирует уже открытое окно. Меню перестраивается
сразу при сохранении в окне настроек;
перезапуск проводника не нужен, но уже открытое меню нужно закрыть.

## DeskEdit (desktop.ini)

Утилита не включает в себя DeskEdit. Скачайте его со страницы
<https://www.sordum.org/10084/desktop-ini-editor-v1-2/>, распакуйте, например в
`C:\Tools\DeskEdit`, и укажите путь:

```
FolderTools.exe set-deskedit "C:\Tools\DeskEdit\DeskEdit_x64.exe"
```

Путь можно задать и в окне настроек, на вкладке «Прочее». Утилита ищет редактор
в таком порядке: `deskEditPath` из `FolderTools.settings.json` (старые сборки
писали его в реестр — это значение читается как запасной вариант), файл рядом
с `FolderTools.exe`, `C:\Tools\DeskEdit\DeskEdit_x64.exe` и
`C:\Tools\DeskEdit\DeskEdit.exe`.

Редактор запускается с путём папки в качестве параметра
(`DeskEdit_x64.exe "D:\My_Folder"`) — такую форму поддерживает сам DeskEdit.

## Команды

| Команда | Действие |
|---|---|
| `FolderTools.exe settings` | Открыть окно настроек |
| `FolderTools.exe -i`, `--install` | Зарегистрировать пункт в контекстном меню папок |
| `FolderTools.exe -r`, `-remove`, `--uninstall` | Убрать пункт из контекстного меню |
| `FolderTools.exe -v`, `--version` | Показать версию |
| `FolderTools.exe nomedia "<папка>"` | Создать или дополнить `.nomedia` |
| `FolderTools.exe shellnew "<файл>"` | Обработать заглушку из меню «Создать» |
| `FolderTools.exe deskedit "<папка>"` | Открыть `desktop.ini` папки в DeskEdit |
| `FolderTools.exe set-deskedit "<путь>"` | Запомнить путь к `DeskEdit.exe` |
| `FolderTools.exe -h`, `--help` | Справка |

Без аргументов открывается окно настроек — так удобнее при запуске двойным
кликом по `FolderTools.exe`. Справка вызывается флагом `-h` / `--help`. Если
утилиту запустили из консоли, результат печатается в неё; при запуске двойным
кликом — показывается окно.

Все настройки хранятся в файле `FolderTools.settings.json` рядом с программой:
папки назначения, шаблоны, категории, иконки, `deskEditPath` и `showSuccess`.
Реестр `HKCU\Software\FolderTools` используется только для регистрации меню
и для чтения значений, записанных старыми версиями.

## Сборка

```
dotnet build FolderTools.sln -c Release
dotnet test src/FolderTools.Tests/FolderTools.Tests.csproj
```

Приложение — это .NET Framework 4.8 (WinForms), поэтому собирается на Windows.
Тесты и ядро — на .NET 8 / netstandard2.0, их можно прогонять и на Linux.
Иконка приложения генерируется скриптом `tools/make_icon.py` в `assets/app.ico`.

CI (GitHub Actions, `.github/workflows/build.yml`) собирает проект и прогоняет тесты.
При пуше тега вида `v1.5.0` версия из тега подставляется в сборку, проверяется,
что она попала в exe, и публикуется релиз с архивом `FolderTools-<версия>.zip`.
При обычном пуше в `main` тот же архив лежит в артефактах прогона.
